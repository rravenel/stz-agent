# 0008 — Doorman, Prime and Com are not integrated end to end

| | |
|---|---|
| **Status** | open |

## Description

Nothing has yet carried a user message from Doorman to Prime, a request from Prime to Com, and the response back to a woken Prime on a deployed stack. Wire the real bundles into the stack and run one full turn against the mock model.

## Long Description

Spec §10 (2:30–3:15), protocol §10 sequence:
- Swap the stub handlers for the real Doorman (#0007), Com (#0006) and Prime (#0013) bundles in the stack; confirm env vars and IAM match what each function reads.
- Integration script under `spikes/integration/` (or a vitest suite gated on an env var) that: POSTs `/wake`, POSTs a message, polls `/events` until the turn ends, and asserts the log shows `wake_sent`, Prime `exit_idle` while Com is mid-request, a second Prime `start`, and the final model response.
- Use the `mock` model with a 60 s delay (success criterion 1).
- Track A owns the stack and the script; Prime-side fixes go to Track B as new B-milestone issues.
- **Needs owner:** deploy (`scripts/deploy.sh`) and run the integration script with AWS credentials.

## Expected behavior

Done when: A person deploys and runs the integration script; the log excerpt showing Prime exiting and being re-woken is attached to the issue.
