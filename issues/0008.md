## Description

Nothing has yet carried a user message from Doorman to Prime, a request from Prime to Com, and the response back to a woken Prime on a deployed stack. Wire the real bundles into the stack and run one full turn against the mock model.

## Long Description

## Plan

Files:
- new `functions/shared/src/s3-object-store.ts` + test;
- new `functions/shared/src/self-wake.ts` + test;
- new `scripts/e2e.ts` + `scripts/e2e.test.ts`. The existing `../scripts/*.test.ts` glob and tsconfig include already cover them;
- `stz_agent/stz_agent_stack.py`, `app.py`, `tests/unit/test_stz_agent_stack.py`.

Don't touch `functions/prime/`, `functions/doorman/`, `functions/com/` or `client/`.

1. **`S3ObjectStore`** (`s3-object-store.ts`) implements Prime's `ObjectStore` structurally. Use `import type { ObjectStore } from "../../prime/src/store.ts"` (type-only, so there's no runtime dependency on Track B code). Constructor `(bucket, client = new S3Client({}))`.
   - `get`: `GetObject` → `transformToByteArray()`; `NoSuchKey` / 404 → null.
   - `put`: `PutObject`.
   - `putIfAbsent`: `PutObject` with `IfNoneMatch: "*"`; `PreconditionFailed` / 412 → false; `ConditionalRequestConflict` / 409 → retry once, then false.
   - `list`: paginate `ListObjectsV2` with `Prefix`, collect `Key`s and sort them.
   - `delete`: `DeleteObject`.
   - Tests use a fake client whose `send(cmd)` switches on `cmd.constructor.name` and records inputs: error mapping, `IfNoneMatch` set, pagination across two pages, sorted output.
2. **`selfWake`** (`self-wake.ts`): `makeSelfWake(functionName, client = new LambdaClient({}))` returns `(event) => Promise<void>`. It does `InvokeCommand({ FunctionName, InvocationType: "Event", Payload: JSON(event) })` and throws if `StatusCode !== 202`. Test it with a fake client.
3. **Stack config** (`stz_agent_stack.py` + `app.py`): new keyword args, each read in `app.py` from CDK context with these defaults:
   - `model_provider` (context `model_provider`, default `"mock"`)
   - `model_name` (default `"mock"`)
   - `openai_base_url` (default unset)
   - `mock_delay_scale` (default unset)
   Prime gets `MODEL_PROVIDER`, `MODEL_NAME` and, when set, `OPENAI_BASE_URL`. Com gets `MOCK_DELAY_SCALE` when set. Validate `model_provider ∈ {mock, anthropic, openai}` in a small `stz_agent/config.py` helper and raise `ValueError` otherwise. No IAM change.
4. **pytest**:
   - Prime's env has `MODEL_PROVIDER=mock` and `MODEL_NAME=mock` by default.
   - Passing `model_provider="openai", openai_base_url=…` sets both.
   - An invalid provider raises.
   - `MOCK_DELAY_SCALE` appears only when given.
   - The existing env-var test still passes; update its expected key set for Prime and Com.
5. **`scripts/e2e.ts`** (Node builtins only, same style as `cost-report.ts`). Usage: `node scripts/e2e.ts --env <name> [--outputs cdk.out/outputs-<name>.json] [--text "..."] [--timeout 600]`.
   - Read `ApiUrl` from the CDK outputs file, which `scripts/deploy.sh` writes. Read the token from `STZ_API_TOKEN` and never print it.
   - Steps:
     1. `POST /wake`.
     2. `POST /messages {msg_id: randomUUID(), text}`. Retry on 503 with the **same** `msg_id`, up to 5 times with 2 s backoff.
     3. Poll `GET /events?after=<seq>` every 2 s until a `model.response` whose body shows the end of the turn, or until `--timeout` expires. Follow `more` pages.
     4. Print a compact timeline, one line per event: `seq ts run kind event/corr`.
     5. Run `checkTurn(events)` and print a PASS/FAIL table. Exit 0 if everything passes, else 1.
   - **`checkTurn` (pure, exported)**, with checks:
     - (a) a `user.message` with our `msg_id`;
     - (b) an `exit_idle` with `pending_requests ≥ 1` (Prime slept while Com held a request);
     - (c) a later `start` in a **different** `run` with reason `wake` (Com woke it);
     - (d) a final `model.response` for the turn;
     - (e) for information, run count, total wall clock, and time between (b) and (c).
     - Each check reports the evidence seq.
   - **Tests** (`e2e.test.ts`): `checkTurn` on a hand-built passing timeline; each check failing on its own; a timeline from a different `msg_id` doesn't count; arg parsing; reading the outputs file. No network.
6. **File Track B issue #0026** on `main` (milestone `B4`), titled "Prime's Lambda entry point is still a stub". Put the exact wiring in its description:
   `export const handler = createHandler({ comms: () => new WorkerComms("prime"), store: new S3ObjectStore(process.env.BUCKET_NAME!), adapter: adapterFromEnv(), selfWake: makeSelfWake(process.env.PRIME_FUNCTION_NAME!) })`

## Run-book

Needs #0026 (Track B: Prime entry point wiring) on `main` first; until then Prime is a stub and check (b) fails.

1. Deploy with the token exported (default model: `mock`, Com's mock delays at full length):
   ```sh
   export STZ_API_TOKEN=<the token you deployed with>
   scripts/deploy.sh
   ```
   `deploy.sh` passes only `-c env=…`. For other settings (e.g. a fast smoke run with `mock_delay_scale=0.1`, or a real model), add a `"context"` entry to `cdk.json` for that run, e.g. `"mock_delay_scale": "0.1"`, or `"model_provider": "openai", "model_name": "…", "openai_base_url": "…"`, then run `scripts/deploy.sh` again and remove the entry afterwards.
2. Run one turn end to end:
   ```sh
   node scripts/e2e.ts --env <your username>
   ```
   Prints `POST /wake → 202 {"wake":"started"}` (or `running`), `POST /messages (try 1) → 202`, then about 3–4 min later (default mock script: 60 s model call + 90 s slow fetch + 5 s) the timeline, one line per event (`seq  ts  run  kind  event/corr`), and the checks:
   ```
   PASS  a user.message            seq …  msg_id …
   PASS  b exit_idle pending>=1    seq …  pending_requests 1
   PASS  c start reason=wake       seq …  new run …
   PASS  d final model.response    seq …  stop end_turn
   info  runs N, wall clock …, exit_idle → wake …
   E2E PASS
   ```
   Exit code 0 on pass, 1 on a failed check, 2 on a usage or HTTP error. `--timeout 600` (s) is the default; `--text "…"` changes the message.
3. Cost for the same window:
   ```sh
   node scripts/cost-report.ts --env <your username> --since 30m --profile stz-dev
   ```
   Prints the per-function GB-s / cost table, the wall clock, the counterfactual and the cost ratio.
