## Description

Com is a stub. It must accept `http.request` messages within its deadline window, stream each response body to S3, and send a terminal `http.response` to Prime, with the `mock` and `none` auth modes working first.

## Long Description

Spec §6, §8; protocol §7.2, §8:
- Uses the comms worker (#0005). On `http.request`: apply the deadline rule (accept only if `now + timeout_s < run_start + 15 min − margin`, else leave it unacked); otherwise ack, delete, dedupe by `request_id`, read the request body from S3, start the request.
- Stream the response to `bodies/<request_id>.res` with `@aws-sdk/lib-storage` `Upload`; never buffer the whole body.
- Terminal `http.response` on success, HTTP error or timeout (per-request `timeout_s`, default 10 min).
- Auth modes: `none`, `mock` (sleep N s, return a scripted Messages-API response; scripts configurable), and `mock://slow?seconds=N&body=...` URLs. Then `anthropic` and `openai` (keys from Secrets Manager, cached per run). `bedrock` (SigV4) is optional for the hackathon; if skipped, file it as a follow-up.
- Exit when nothing is in flight, the unacked set is empty and a final poll is empty.
- Unit tests with the in-memory fake: deadline rule, dedupe, mock model script, slow URL, terminal response on timeout.

## Plan

Files: `functions/shared/src/comms-core.ts` + `comms-core.test.ts` (step 1 only), and new files in `functions/com/src/`: `index.ts` (replaces the stub), `com.ts`, `auth.ts`, `mock.ts`, `aws.ts`, `com.test.ts`, `mock.test.ts`, `auth.test.ts`; update `index.test.ts`. No stack changes. Don't touch `functions/prime/` or `functions/doorman/`.

1. **Deadline-aware ack (`comms-core.ts`)**: add `CommsOptions.acceptDeadlineAtMs?: number` (it serializes, so it travels in `workerData` unchanged).
   - In `handle()`, for `http.request` when the option is set: if `Date.now() + body.timeout_s * 1000 > acceptDeadlineAtMs`, **don't ack, don't hand off, don't delete**. Log `{kind: "declined", msg_id, reason: "deadline"}` and return. The message reappears after the visibility timeout. Prime keeps waking Com (429 while this one runs), and the next Com takes it.
   - Default unset means today's behaviour, so Prime and Doorman are unaffected. Add `"declined"` to `LogEvent`.
   - Tests: declined when it doesn't fit, acked when it does, unaffected when unset, never applied to other types.
2. **`index.ts` handler** `(event, context)`:
   - Compute `deadline = Date.now() + context.getRemainingTimeInMillis() − MARGIN_MS` (60 s).
   - Start `new WorkerComms("com", { comms: { acceptDeadlineAtMs: deadline } })` **first**.
   - Build `ComCore` with the AWS adapters from `aws.ts` and `await core.run()`. Then `await comms.stop()` and return `{ handled, declined }`.
   - Doesn't throw on a bad event; logs JSON lines.
3. **`ComCore` (`com.ts`)**, with everything injected: `comms: Comms`, `store`, `secrets`, `fetch`, `sleep`, `now`, `log`.
   - On `http.request`:
     - **Dedupe**: a `request_id` that's in flight or done in this run → delete and skip.
     - Otherwise **delete immediately** (protocol §6: Com deletes on accept) and register it in flight.
     - Read `body_ref` via `store.getText` when present.
     - Dispatch: any `mock://` URL → `mock.ts`; else build headers via `auth.ts` → `fetch(url, {method, headers, body, signal: AbortSignal.any([timeout(timeout_s), runAbort])})`.
   - **Stream** the response body to `responseBodyKey(request_id)` with `store.putStream(key, readable, contentType)` and count the bytes as they pass. Never buffer the whole body.
   - **Terminal `http.response`** (always exactly one per accepted request):
     - success or HTTP error: `ok = res.ok`, `status`, a few headers (`content-type`, `request-id` / `x-request-id`), `body_ref`, `bytes`, `elapsed_ms`;
     - timeout: `ok: false, error: "timeout after Ns"`;
     - network or store failure: `ok: false, error`.
     - Send it with `comms.send("prime", "http.response", …)`.
   - Messages of other types: log and delete.
   - **`run()` exits** when in-flight = 0 and `comms.unackedCount() === 0` and `await comms.finalPoll(2000)` is true (protocol §7.2). Check every 250 ms. If remaining run time < 10 s, abort what's in flight, log `exit_deadline` and return; those requests die by design (spec §6).
4. **`auth.ts`**: `applyAuth(req, secrets) → headers`.
   - `none` and `mock`: unchanged.
   - `anthropic`: `x-api-key`.
   - `openai`: `Authorization: Bearer <key>` for the longest matching base-URL prefix.
   - `bedrock`: throw `UnsupportedAuth`, which becomes a terminal `ok:false, error:"bedrock auth not implemented"`.
   - Secret JSON (document it in the file header and in `## Fix`): `{"anthropic": "<key>", "openai": {"https://api.openai.com/v1": "<key>", "<other base url>": "<key>"}}`.
   - `secrets.get()` fetches `MODEL_SECRET_ARN` once per run and caches it.
   - Never log keys or headers.
   - After resolving, file a follow-up issue for Bedrock SigV4 on `main`, in milestone A4 or later.
5. **`mock.ts`**:
   - `mock://slow?seconds=N&body=TEXT`: sleep N s, then a 200 with `TEXT`.
   - `mock://model`: parse the request JSON and choose the step as the count of `role: "assistant"` messages in `messages`. This makes it stateless across Com runs. Sleep `step.delay_s`, then return an Anthropic Messages response `{id, type: "message", role: "assistant", model, content, stop_reason, usage}`. Past the end of the script, repeat the last step.
   - The script is loaded per request from S3 `mock/script.json` if present, else the built-in default, so the demo can change it without a redeploy.
   - **Default script**:
     - step 0 (`delay_s: 60`): `tool_use` `repl` with code that sets `globalThis.greet = (n) => "hi " + n`, awaits `fetch("mock://slow?seconds=90&body=slow-ok")` and returns both;
     - step 1 (`delay_s: 5`): a text answer with `end_turn`.
   - `MOCK_DELAY_SCALE` env (default 1) multiplies delays, for quick live runs.
6. **`aws.ts`** (SDK adapters, thin, no logic):
   - `S3Store.getText`;
   - `S3Store.putStream` via `new Upload({ client, params: { Bucket, Key, Body: Readable.fromWeb(body), ContentType } }).done()`;
   - `S3Store.getJSONOrNull` for the mock script, where `NoSuchKey` → null;
   - `SecretsSource` via `GetSecretValueCommand`.
7. **Tests** (`node:test`; `InMemoryBus`/`InMemoryComms` for comms; a fake store that drains streams into memory; a fake fetch; injected `sleep`/`now`, or `mock.timers`):
   - dedupe (the same `request_id` twice → one fetch, one response);

   - the body goes through `putStream`, and the byte count matches;
   - the mock model picks the step from the assistant-message count, has a default script, an S3 override and a delay scale;
   - slow URL parsing and its delay;
   - auth headers per mode, longest-prefix OpenAI key, Bedrock → terminal error, the secret fetched once;
   - `run()` exits only when in-flight = 0, unacked = 0 and the final poll is empty, and doesn't exit while a response is unacked;
   - plus the step 1 tests in `comms-core.test.ts`.
8. **Verify**: with the usual exports, `scripts/check.sh` → `CHECK OK`, and the new tests show up in `test-functions`. `build-functions` must still bundle `com` (lib-storage stays external).
