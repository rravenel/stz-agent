## Description

There is no `client/` CLI. It needs to pre-wake Prime on start, send messages with a client-generated `msg_id` and retry on 503, and poll `/events` to print the turn as it happens.

## Long Description

Spec §7:
- `client/` TS package with the `typecheck`/`build`/`test` npm scripts (see the TS package contract in `Issues.md`).
- On start: `POST /wake`. REPL loop: read a line, `POST /messages` with a fresh UUID `msg_id`; on `503` retry with the **same** `msg_id` (bounded backoff).
- Sequential: no `GET` while a `POST` is outstanding. After `202`, poll `GET /events?after=<seq>` every 1–2 s and print events until the turn ends (`model.response` with no tool calls).
- API URL and token from env vars or a flag; never logged.
- Unit tests with a fake HTTP server: retry keeps `msg_id`, polling stops at end of turn.

## Expected behavior

Done when: `scripts/check.sh` → `CHECK OK` with a `test-client` line. Live use is part of #0017.
