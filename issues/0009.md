## Description

There is no `client/` CLI. It needs to pre-wake Prime on start, send messages with a client-generated `msg_id` and retry on 503, and poll `/events` to print the turn as it happens.

## Long Description

Spec §7:
- `client/` TS package with the `typecheck`/`build`/`test` npm scripts (see the TS package contract in `Issues.md`).
- On start: `POST /wake`. REPL loop: read a line, `POST /messages` with a fresh UUID `msg_id`; on `503` retry with the **same** `msg_id` (bounded backoff).
- Sequential: no `GET` while a `POST` is outstanding. After `202`, poll `GET /events?after=<seq>` every 1–2 s and print events until the turn ends (`model.response` with no tool calls).
- API URL and token from env vars or a flag; never logged.
- Unit tests with a fake HTTP server: retry keeps `msg_id`, polling stops at end of turn.

## Plan

Files (all new): `client/package.json`, `client/tsconfig.json`, `client/build.mjs`, `client/README.md` (usage), and in `client/src/`: `api.ts`, `turn.ts`, `format.ts`, `cli.ts`, `api.test.ts`, `turn.test.ts`, `format.test.ts`. No other paths.

1. **Package**:
   - `package.json`: `"name": "stz-client"`, `"private": true`, `"type": "module"`, `"engines": {"node": ">=22.18"}`.
   - Scripts: `typecheck` (`tsc --noEmit -p .`), `build` (`node build.mjs`), `test` (`node --test --test-reporter=spec "src/**/*.test.ts"`).
   - devDependencies: copy the exact ranges for `typescript`, `esbuild` and `@types/node` from `functions/package.json`.
   - `tsconfig.json`: mirror `functions/tsconfig.json` (strict, NodeNext, `erasableSyntaxOnly`, `allowImportingTsExtensions`, `noEmit`, `types: ["node"]`), with `include: ["src/**/*.ts"]`.
   - `build.mjs`: esbuild `src/cli.ts` → `dist/cli.mjs` (node22, esm, bundle, no externals needed). `client/dist/` is already git-ignored.
2. **`api.ts`**: `class Api { constructor({ baseUrl, token, fetch = globalThis.fetch, sleep }) }`.
   - `wake()` → `{status, wake}`.
   - `postMessage(text, msgId = randomUUID())`: on 503 (or a network error), retry with the **same** `msg_id`, up to 6 attempts with backoff 1, 2, 4, 8, 8 s (injectable `sleep`). It returns `{msg_id, attempts}` on 202 and throws `ApiError` after the last 503. 401 or other 4xx → throw at once, with no retry.
   - `events(after, limit = 200)` → `{events, next_after, more}`.
   - Trim a trailing slash from `baseUrl`. **Never** put the token in an error message or a log line. An error includes the method, path and status only.
3. **`turn.ts`** (`runTurn(api, text, { print, sleep, pollMs = 1500, timeoutMs = 15 * 60_000, after })`):
   - **Sequential**: `await api.postMessage(...)` first, and only then start polling, so there's never a GET while a POST is outstanding.
   - Poll `events(after)`. Follow `more` immediately; otherwise wait `pollMs`. Print each event via `format.ts` and advance `after = next_after`.
   - Stop at end of turn (the rule in Prerequisites), but **only for events after our `user.message`** (match `msg_id`).
   - Return `{ after, ended: "end_turn" | "error" | "timeout" }`. The caller keeps `after` across turns.
   - `isEndOfTurn(ev)` is exported and pure.
4. **`format.ts`**: one line per event, with no colour dependency (use ANSI dim only when `stdout.isTTY`).
   - `user.message` → `you: …`;
   - `model.response` → its text blocks joined, plus `→ repl(...)` with the first line of the code for each `tool_call`;
   - `tool.result` → `← value/error` (truncated to 200 chars);
   - `http.request` / `http.response` → `· com <purpose> <status> <elapsed>`;
   - `lifecycle` → `· prime <event> (<reason>)`;
   - `error` → `! <message>`.
   - Unknown kinds print as `· <kind>`.
5. **`cli.ts`**: `node client/src/cli.ts [--url URL] [--token-env NAME]` (or `node client/dist/cli.mjs`).
   - The URL comes from `--url`, else `STZ_API_URL`. The token comes from the env var named by `--token-env` (default `STZ_API_TOKEN`); never take the token as a flag, so it doesn't end up in shell history or `ps`.
   - On start: `wake()`, then get the current tail (page `events` until `more` is false) so old history isn't replayed.
   - Then a `node:readline` loop: each line → `runTurn`. `/quit` exits. `/clear` is sent as text (Doorman/Prime handle it).
   - Ctrl-C exits cleanly.
   - Print the URL but never the token.
6. **Tests** (`node:test`, with a real `node:http` server on port 0 as the fake Doorman that records requests; inject `sleep` as a no-op recorder):
   - (a) 503, 503, 202 → three POSTs with the **same** `msg_id`, and `attempts === 3`;
   - (b) 401 → throws without retrying;
   - (c) every request carries the bearer header, and the token appears in no thrown message;
   - (d) `runTurn` polls until a `model.response` without tool calls, after one that had a tool call, then stops, and makes no further GETs;
   - (e) an `error` with `where: "model.response"` ends the turn;
   - (f) events from an earlier turn (a different `msg_id`) don't end this turn;
   - (g) the fake server asserts that no GET arrives while a POST is in flight;
   - (h) a timeout returns `ended: "timeout"`;
   - (i) `format.ts` lines for each kind;
   - (j) `more: true` pagination is followed without waiting.
7. **Verify**: with the usual exports, `scripts/check.sh` → `CHECK OK`, with `typecheck-client`, `build-client` and `test-client` lines. Paste them into `## Verification`.
8. **Git** (per `Issues.md`): code commits go on the branch; issue-file edits go on `main` only. Stage by path: `client/node_modules` is a symlink and must **not** be committed. `node_modules/` in `.gitignore` doesn't match a symlink, so check `git status` before committing.
