## Description

`scripts/cost-report.ts` defaults `--region` to `us-west-2` and always passes it to `aws logs filter-log-events`, so a stack deployed elsewhere (or a profile with a different region) reads the wrong log groups and reports zero invocations. Follow-up from the #0010 review.

## Prerequisites

Probed by planner on 2026-11-21 at `main` `6bb6cba`.

- [x] Worktree `.worktrees/0030-cost-report-region` on `track-a/0030-cost-report-region`, with the `.venv`, `functions/node_modules` and `client/node_modules` symlinks.
- [x] The only region uses are `scripts/cost-report.ts` lines ~162 (usage), 174 (`default: "us-west-2"`), 203 and 215 (`"--region", o.region`). The AWS CLI already resolves the region itself from `AWS_REGION` / `AWS_DEFAULT_REGION` / the profile when `--region` is omitted.
- No overlap with #0025 (Com and stack) or #0031/#0032 (stack, tests, Doorman). Only `scripts/cost-report.ts` and its test.

## Plan

1. Remove the `us-west-2` default: `region?: string` in `CliOptions`. If `--region` is given, pass it; otherwise pass **no** `--region` and let the AWS CLI resolve it (`AWS_REGION`, `AWS_DEFAULT_REGION`, then the profile's `region`). Update `USAGE` to `[--region R (default: AWS_REGION / profile)]`.
2. Factor the CLI argument list out of `fetchReports` into a pure exported `logsArgs(group, o): string[]` so it can be tested.
3. Keep the pricing constant as is, but rename its comment to "x86_64, us-west-2 list price". Region-specific pricing is out of scope.
4. Tests (`scripts/cost-report.test.ts`): `parseCli` without `--region` gives `region` undefined, and `logsArgs` has no `--region`; with `--region eu-west-1`, `logsArgs` includes `--region eu-west-1`; `--profile` is still passed through.
5. Verify: with the usual exports, `scripts/check.sh` → `CHECK OK` with the new tests counted. `node scripts/cost-report.ts --help` shows the new usage.
6. Git: code commits go on the branch; issue-file edits go on `main` only. Stage by path.

## Expected behavior

Done when: `scripts/check.sh` → `CHECK OK`; with no `--region`, the report uses the CLI's own region resolution.
