# 0032 — Doorman's API token is plaintext in the template and cdk.out

| | |
|---|---|

| **First seen** | 2026-11-21 |

## Description

Doorman's bearer token is passed as the `API_TOKEN` Lambda env var from `STZ_API_TOKEN` / `-c api_token` at synth time, so it is written in plaintext into the CloudFormation template, `cdk.out/` and the Lambda console. Move it to Secrets Manager: CDK generates it, only Doorman can read it, and people fetch it with the AWS CLI. Follow-up from the #0003 review.

## Plan

1. **Stack**:
   - Add `api_token_secret = secretsmanager.Secret(self, "ApiToken", description="Doorman bearer token", generate_secret_string=secretsmanager.SecretStringGenerator(password_length=48, exclude_punctuation=True))`. CDK generates the value at deploy time, so it never appears in the template.
   - Doorman gets `API_TOKEN_SECRET_ARN` instead of `API_TOKEN`, and `api_token_secret.grant_read(doorman)`. Doorman only.
   - Output `ApiTokenSecretArn`.
   - Remove the `api_token` constructor argument.
2. **`app.py` / `config.py`**: delete `resolve_api_token` and `BUILD_PLACEHOLDER_TOKEN`, so deploy no longer needs `STZ_API_TOKEN`. Keep the model-config helpers.
3. **Doorman**:
   - `Deps.token` becomes `token: () => Promise<string>`, backed by a `cachedSecret(load)` helper in `functions/doorman/src/aws.ts`: one in-flight load is shared, a failed load is retried next time, and the value is cached for the container's lifetime. The load is `GetSecretValueCommand({ SecretId: API_TOKEN_SECRET_ARN })` → `SecretString`.
   - `route` awaits it before `authorized(...)`. If the load throws, return `503 {error: "auth unavailable"}`, never 401 or 200, and log the error without any secret material.
   - Keep the constant-time compare.
4. **Tests**:
   - pytest:
     - no `API_TOKEN` key in any function's env;
     - Doorman has `API_TOKEN_SECRET_ARN`;
     - the template contains no plaintext token (search the synthesized JSON for `test-token` / `build-placeholder`);
     - the `ApiToken` secret has `GenerateSecretString`;
     - `GetSecretValue` on the token secret is granted only to Doorman's role, and on the model secret only to Com's (replace `test_only_com_reads_secret` with these two);
     - `ApiTokenSecretArn` is an output;
     - drop `test_resolve_api_token` and every `api_token=` argument.
   - Doorman TS tests: a token loaded once across many requests; a failed load → 503, then a retry succeeds on the next request; a wrong token → 401; no token text in captured logs.
5. **Docs and run-books**:
   - In `issues/0023.md` (on `main`), replace "`STZ_API_TOKEN` set as in #0022" with:
     `export STZ_API_TOKEN=$(aws secretsmanager get-secret-value --profile stz-dev --secret-id <ApiTokenSecretArn output> --query SecretString --output text)`.
     Put the same line in `client/README.md` and the `scripts/e2e.ts` usage text.
   - In `README.md`, drop any deploy-time `STZ_API_TOKEN` requirement.
6. **Verify**: with the usual exports, `scripts/check.sh` → `CHECK OK`.
7. Git: code commits go on the branch; issue-file edits go on `main` only. Stage by path.

## Expected behavior
