## Description

`tests/unit/test_stz_agent_stack.py::test_queue_permissions` only asserts that each function's role has *some* `sqs:ReceiveMessage` and *some* `sqs:SendMessage`. A regression that let Doorman send to `com-messages`, or let Com consume `prime-messages`, would pass. Follow-up from the #0003 review.

## Prerequisites

Probed by planner on 2026-11-21 at `main` `6bb6cba`.

- [x] **#0025 is on `main`** (`8b2e14b`), so no conflict is left. Worktree `.worktrees/0031-queue-perms-test` on `track-a/0031-queue-perms-test`, with the three symlinks.
- [x] The intended matrix (spec §2 diagram, #0003 plan step 7): **consume** (Receive/Delete/ChangeVisibility) on its own queue only; **send**: Doorman → `prime-messages`; Prime → `doorman-messages`, `com-messages`; Com → `prime-messages`. The S2 spike functions (when present) have **no** SQS permissions.
- [x] In the template, queue resources appear as `{"Fn::GetAtt": ["<LogicalId>", "Arn"]}`. The logical IDs start with `DoormanMessages`, `PrimeMessages` and `ComMessages`, and the DLQs `PrimeMessagesDlq…` / `ComMessagesDlq…` must not be confused with them, so match exact construct-path prefixes, not substrings.

## Plan

1. A helper `queue_ids(template)` maps `"doorman" | "prime" | "com"` → the logical ID of the main queue. Find `AWS::SQS::Queue` resources with `aws:cdk:path` metadata ending in `/DoormanMessages/Resource`, and so on. If metadata is absent in tests, fall back to the logical ID prefix and exclude `Dlq`.
2. A helper `sqs_targets(template, fn_key, action)` → the set of queue keys whose ARN appears in a statement that grants `action` to that function's role, reusing `role_statements`.
3. Replace `test_queue_permissions` with exact assertions: `ReceiveMessage` → `{own}` for each function; `SendMessage` → the matrix above. Add a test that the S2 spike functions (with `spike_s2=True`) have no `sqs:*` actions at all.
4. If an assertion fails, **the stack is wrong**: fix `stz_agent_stack.py` to match the matrix and say so in `## Fix`.
5. Verify: with the usual exports, `scripts/check.sh` → `CHECK OK` with the pytest count up.
6. Git: code commits go on the branch; issue-file edits go on `main` only. Stage by path.

Branch `track-a/0031-queue-perms-test`: `queue_ids()` (by `aws:cdk:path`, DLQs excluded) and `sqs_targets()` helpers; `test_queue_permissions` now asserts consume actions → own queue only and `SendMessage` → the exact matrix; new `test_spike_s2_has_no_sqs` and `test_queue_ids_skip_dlqs`. The stack already matched; no stack change. pytest 25 → 27, `CHECK OK`.
