## Description

`functions/prime/src/index.ts` exports `createHandler` but its `handler` still returns `{stub: "prime"}`, so a deployed Prime never polls its queue, restores, or runs the loop. Wire the real dependencies. Filed by Track A from #0008 planning: `functions/prime/` is Track B's path.


## Root cause

`functions/prime/src/index.ts` still exported the stub `handler`, so a deployed Prime never ran the harness.

## Fix

Branch `track-b/0026-prime-entry`, commit `64ef3d0`. It follows the `## Plan`.

- **`primeDepsFromEnv(env, make = awsFactories)`** returns `PrimeDeps`:
  - `comms: () => new WorkerComms("prime")`, one per run;
  - `store: new S3ObjectStore(BUCKET_NAME)`;
  - `adapter: adapterFromEnv(env)`;
  - `selfWake: makeSelfWake(PRIME_FUNCTION_NAME)`.

  If `BUCKET_NAME` or `PRIME_FUNCTION_NAME` is missing, it throws one error naming both. Bad model config throws `adapterFromEnv`'s own error.
- **`handler`** builds `createHandler(primeDepsFromEnv(process.env))` on its first invocation and reuses it. If building fails, the invocation fails and the next one tries again.
- **Nothing happens at import,** because `WorkerComms` re-executes this bundle in a worker thread, and a config error should fail an invocation, not the module load. The SDK clients make no network calls until their first `send`.
- **No changes to Track A files.** It uses `WorkerComms`, `S3ObjectStore` and `makeSelfWake` exactly as #0005 and #0008 shipped them.

## Long Description

Track A's #0008 adds the AWS pieces in `functions/shared/src/` (Track A-owned): `S3ObjectStore` (`s3-object-store.ts`, implements Prime's `ObjectStore`) and `makeSelfWake` (`self-wake.ts`, async `Event` invoke). The comms worker is `WorkerComms` (`comms-worker.ts`, #0005). With those on `main`, the change is roughly:

```ts
import { createHandler } from "./handler.ts";
import { adapterFromEnv } from "./models/config.ts";
import { WorkerComms } from "../../shared/src/comms-worker.ts";
import { S3ObjectStore } from "../../shared/src/s3-object-store.ts";
import { makeSelfWake } from "../../shared/src/self-wake.ts";

export const handler = createHandler({
  comms: () => new WorkerComms("prime"),
  store: new S3ObjectStore(process.env.BUCKET_NAME!),
  adapter: adapterFromEnv(),
  selfWake: makeSelfWake(process.env.PRIME_FUNCTION_NAME!),
});
```

The stack (after #0008) sets `MODEL_PROVIDER` (default `mock`), `MODEL_NAME`, `OPENAI_BASE_URL` when configured, plus `BUCKET_NAME`, the queue URLs and function names. Keep `index.test.ts` meaningful (e.g. the module loads and `handler` is a function; no AWS calls at import time).

## Plan

Files: `functions/prime/src/index.ts` and `functions/prime/src/index.test.ts`. Only Track B paths.

1. **No side effects at import.** The issue's sketch builds the store and the adapter at module scope, which has two problems:
   - **The worker re-imports the bundle.** `WorkerComms` starts its worker by re-executing the bundle file itself (`new Worker(import.meta.url)`), so the comms worker imports all of `index.mjs`.
   - **Bad config would fail the import.** `adapterFromEnv()` throws on missing config, so the module would fail to load in tests or in that worker.

   So `index.ts` exports:
   - **`primeDepsFromEnv(env, make = defaultFactories)`:** checks `BUCKET_NAME`, `PRIME_FUNCTION_NAME` and the model config, and throws one error that names every missing variable. It returns `PrimeDeps`: `comms: () => make.comms("prime")`, `store: make.store(bucket)`, `adapter: adapterFromEnv(env)`, `selfWake: make.selfWake(functionName)`. The factories wrap `new WorkerComms`, `new S3ObjectStore` and `makeSelfWake`; tests pass fakes.
   - **`handler(event, context)`:** on the first call it builds `createHandler(primeDepsFromEnv(process.env))` and keeps it for the container's lifetime, then delegates. Construction makes no AWS calls; the SDK clients connect only on the first `send`.
2. **Cold-start work** (spec §5.1 step 1: compile the wasm at init). `loadWasm()` already caches per process. Call it on the first invocation rather than at import, so the worker thread doesn't pay for it. The QuickJS compile happens in `Repl.create`/`restore` on each run. Moving that to init is an optimization for later (#0020 measures it).
3. **Replace the stub tests in `index.test.ts`:**
   - Importing `index.ts` with an empty env succeeds, and `handler` is a function.
   - `primeDepsFromEnv` with fakes passes the bucket name to the store factory and the function name to the self-wake factory. `comms()` creates a `"prime"` comms on each call, not at construction. The adapter matches `MODEL_PROVIDER`.
   - A missing `BUCKET_NAME` or `PRIME_FUNCTION_NAME` names both in the error.
   - Calling `handler` with the env missing rejects with that error and makes no AWS call.
4. **Bundle check:** after `scripts/build.sh`, import `functions/dist/prime/index.mjs` and confirm that `handler` and `primeDepsFromEnv` are exported and the import has no side effects (no env needed). This check is recorded in `## Verification`. It isn't a test, because `test.sh` can run without a build.
