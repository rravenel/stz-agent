## Description

Both tracks need one agreed definition of the SQS envelope, the S3 key layout and Prime's `state.json`, plus a comms-worker interface Track B can code against before the real worker exists. None of these exist yet.

## Long Description

- `functions/shared/envelope.ts`: the envelope and the four body types exactly as protocol §3 (`user.message`, `http.request`, `http.response`, `ack`), with a runtime validator (`parseEnvelope`) and a constructor that fills `v`, `msg_id`, `sent_at`.
- `functions/shared/s3-keys.ts`: key builders for spec §4 (`log/<seq:010d>.json`, `bodies/<id>.req|.res`, `prime/ckpt-<n>/state.json|repl.bin`, `prime/latest.json`, `workspace/...`).
- `functions/shared/state.ts`: the `state.json` type from spec §5.4 and the log event type from §4.1.
- `functions/shared/comms.ts`: the interface the main thread uses to talk to its comms worker (send, `onMessage(msg, receiptHandle)`, `deleteMessage`, `unackedCount`, `finalPoll`, `stop`) and an **in-memory fake** implementing it, so Prime (Track B) and Com/Doorman (Track A) can be tested before #0005 lands.
- Unit tests: envelope round-trip and rejection of bad shapes; key formatting (zero-padded seq).
- This is the contract milestone: Track B reviews it before it merges.

## Decisions taken without the owner

- **`parseEnvelope` returns `{ok, value | error}` and never throws**, so a poison message can be logged and deleted without a try/catch around every receive.
- **Key builders refuse unsafe IDs** (`/`, `..`, empty) and workspace paths that are absolute or contain `.`/`..` segments. `request_id` values are ours, but REPL file paths come from model-written code.
- **The comms fake is an in-memory bus with one `InMemoryComms` per endpoint.** Calling `connect()` again models a woken function; `stop()` models exit or crash, and messages that were received but not deleted become visible again. Delivery is asynchronous (microtask), so a handler never runs inside `send()`. It doesn't model the delivery monitor or wakes; that's #0005. **Wants owner feedback:** Track B, please confirm the `Comms` interface (`send`, `onMessage`, `deleteMessage`, `unackedCount`, `finalPoll`, `stop`) covers what Prime needs (spec §5.1, §5.5) before #0005 builds the real worker against it.
- **Imports are relative** (`../../shared/src/envelope.ts`), as decided in #0001.

## Root cause

There were no shared contracts: no envelope, S3 key layout, state types or comms interface for either track to code against.

## Fix

Added `functions/shared/src/{envelope,s3-keys,state,comms}.ts`, following protocol §3, §5–6 and spec §4, §4.1, §5.4.
