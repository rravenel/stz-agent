## Description

Both tracks need one agreed definition of the SQS envelope, the S3 key layout and Prime's `state.json`, plus a comms-worker interface Track B can code against before the real worker exists. None of these exist yet.

## Long Description

- `functions/shared/envelope.ts`: the envelope and the four body types exactly as protocol §3 (`user.message`, `http.request`, `http.response`, `ack`), with a runtime validator (`parseEnvelope`) and a constructor that fills `v`, `msg_id`, `sent_at`.
- `functions/shared/s3-keys.ts`: key builders for spec §4 (`log/<seq:010d>.json`, `bodies/<id>.req|.res`, `prime/ckpt-<n>/state.json|repl.bin`, `prime/latest.json`, `workspace/...`).
- `functions/shared/state.ts`: the `state.json` type from spec §5.4 and the log event type from §4.1.
- `functions/shared/comms.ts`: the interface the main thread uses to talk to its comms worker (send, `onMessage(msg, receiptHandle)`, `deleteMessage`, `unackedCount`, `finalPoll`, `stop`) and an **in-memory fake** implementing it, so Prime (Track B) and Com/Doorman (Track A) can be tested before #0005 lands.
- Unit tests: envelope round-trip and rejection of bad shapes; key formatting (zero-padded seq).
- This is the contract milestone: Track B reviews it before it merges.

## Expected behavior

Done when: `scripts/check.sh` → `CHECK OK`, with the new envelope/key tests in the `test-functions` count.
