## Description

Owner issue (AWS). #0004 writes the spike S2 code and a run-book; agents have no AWS credentials, so a person deploys the stack and runs it. This is also the first real deploy of the #0003 stack, so it catches IAM, env-var and bundle mistakes early.

## Steps (person)

1. One-time checks:
   - `aws sso login --profile stz-dev`
   - `aws lambda get-account-settings --profile stz-dev --query AccountLimit.ConcurrentExecutions` → must be **≥ 104** (Doorman, Prime, Com and the S2 target reserve 1 each; AWS keeps 100 unreserved). If lower, request a quota increase first.
   - `export STZ_API_TOKEN=<any long random string>` (Doorman's bearer token; keep it for the client later).
   - If the account/region was never bootstrapped: `functions/node_modules/.bin/cdk bootstrap --profile stz-dev`.
2. `scripts/deploy.sh` (deploys `StzAgent-<your username>`). Paste the stack outputs.
3. Follow the **Run-book** section in `issues/0004.md` exactly and paste its output.
