## Description

Prime has no `repl(code)` tool. Build the QuickJS wrapper the spike chose: wrapped async evals tracked in `__evals`, a `fetch` that parks promises in `__pending`, host functions registered in a fixed order, a CPU limit, no timers, and `/workspace` file access.


## Root cause

Prime had no REPL: the QuickJS snapshot/restore technique existed only as spike code (`spikes/s1-quickjs/`, #0011), with four open review notes.

## Fix

Branch `track-b/0012-repl`, `functions/prime/src/repl/`:
- **`quickjs.ts`**: the S1 driver, ported with all four #0011 review notes fixed:
  1. argv is re-read after each argument conversion, because converting an argument can grow memory and detach the view;
  2. `runJobs()` collects job exceptions instead of stopping silently;
  3. a host function that throws becomes a JS `Error` (`JS_NewError` + `JS_Throw`) instead of unwinding through wasm;
  4. `snapshot()` throws while QuickJS is running (inside a host call).

  Strings are read by length, so `"\0"` survives.
- **`repl.ts`** (`Repl`): `create`, `restore(snapshot)`, `eval(toolCallId, code)` → `{status:"done", value?, stdout, stderr, error?}` or `{status:"pending"}`, `resolvePending`/`rejectPending(requestId, …)`, `take(id)`, `pendingRequests()`, `pendingEvals()`, `snapshot()`.
  - **Evals** are wrapped as `__runEval(id, async () => {code})`, per the spec.
  - **`fetch(url, {method, headers, body})`** stores `{resolve, reject}` in `__pending["rN"]` and calls `onFetch({requestId, url, method, headers, body})`. The proxy is wired in #0013. The response object has `status`, `ok`, `headers.get`, `text()` and `json()`. The request counter lives in the snapshot, so ids stay unique across Prime runs.
  - **Host functions** `__host_fetch`, `__host_log` and `__host_fs` are registered in a fixed order, then deleted from `globalThis` by the prelude, so model code reaches the host only through `fetch`, `console` and `fs`.
  - **CPU limit** is 30 s per host→REPL call, an eval or a fetch resolution (`cpuLimitMs`). The interrupt is uncatchable, and after a 1 s grace every further check trips.
  - **No timers.**
  - **Console output** goes to `__io` inside the snapshot (64 KB per stream per eval) and is mirrored to `onOutput`.
- **`workspace.ts`**: the `fs` global (`readFile`, `writeFile`, `appendFile`, `readdir`, `mkdir`, `rm`, `exists`, `stat`, UTF-8 text) maps `/workspace` to `/tmp/workspace` (`workspaceDir`). A path is rejected if it escapes `/workspace` through `..`, an absolute path or a symlink. Error messages show `/workspace` paths, not host paths.
- **`wasm.ts`**: the pinned `qjs-wasi-reactor.wasm` (v0.18.0) is vendored in `functions/prime/vendor/` (1.5 MB) and checked against its SHA-256 on every load. It is looked up at `$STZ_QJS_WASM`, then next to the bundle, then in `vendor/`.
- **`webassembly.d.ts`**: minimal `WebAssembly` typings. `@types/node` lacks them, and the shared tsconfig is Track A's, so I didn't widen its `lib`.

**Decisions not in the plan** (there was no planning phase; I did the planning myself):
- **Vendor the wasm** rather than download it at build time. Tests and `check.sh` then work offline and in the sandbox.
- **CPU limit hit in code resumed by `resolvePending`:** a promise job doesn't say which eval it belongs to, so every eval still pending is failed with the CPU-limit error. Prime has one open tool call at a time.

## Gotchas

- **Declarations are local to an eval.** That follows from the spec's async-function wrapping. Keep state on `globalThis`, and say so in the model's system prompt in #0013.
- **The bundle doesn't ship the wasm yet.** `functions/build.mjs` must copy `prime/vendor/qjs-wasi-reactor.wasm` to `dist/prime/` before Prime is deployed. `build.mjs` is shared build infrastructure, so this goes to #0013 or Track A. Nothing imports the REPL from `index.ts` yet, so today's bundle is unaffected.
- **Console output belongs to the next eval that settles.** If two evals are pending at once, their output can be mixed.

## Long Description

Spec §5.2, §5.3:
- `functions/prime/repl/`: create/restore instance, `eval(tool_call_id, code)` wrapping as `__evals[id] = {status:"pending"}; (async () => { <code> })().then(...)`, run pending jobs to quiescence, return `{value, stdout, stderr, error}` or "pending".
- `fetch(url, opts)` → `__host_fetch` → proxy callback (wired in #0013); resolver stored in `globalThis.__pending[request_id]`; `resolvePending(id, response)` / `rejectPending(id, err)` from the host.
- Host functions (`__host_fetch`, `__host_log`, fs bindings for `/workspace` → `/tmp/workspace`) registered in the **same order on every boot**.
- Eval CPU limit 30 s via the interrupt handler; `setTimeout`/`setInterval` not provided.
- `snapshot()` / `restore(bytes)` per the S1 result (or the replay fallback).
- Unit tests: settled eval, pending eval resolved later, CPU limit, no timers, snapshot → new instance → resolve pending.
