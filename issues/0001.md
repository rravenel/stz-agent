## Description

There is no `functions/` npm workspace, so neither track has anywhere to put TypeScript or a way to build and test it. Create the workspace with the `typecheck`, `build` and `test` scripts that `scripts/build.sh` and `scripts/test.sh` expect.

## Long Description

- `functions/package.json` as an npm workspace with packages `shared`, `doorman`, `prime`, `com` (spec §9). Node 22+ target, ESM, `@aws-sdk/*` v3 as dev deps (the Lambda runtime provides them).
- npm scripts at the workspace root: `typecheck` (`tsc --noEmit -p .`), `build` (esbuild bundles one file per function into `functions/dist/<name>/index.mjs`), `test` (`vitest run`).
- One trivial vitest test per package so `scripts/test.sh ts` proves the wiring (it fails on zero tests).

- **Needs owner:** a person runs `scripts/setup.sh` after this lands (agent sandboxes can't install packages).

## Decisions taken without the owner

- **Tests run on `node --test`, not vitest.** Node 26 runs `.ts` files directly, so the suite needs no installed packages. That matters because agent sandboxes can't reach the npm registry, and the local npm cache has no vitest or typescript. vitest would also pull in a bundler toolchain. The `functions/package.json` `test` script is the only place this lives; switching to vitest later is a one-line change, and `scripts/test.sh` reads both summary formats. **Wants owner feedback:** keep `node --test` for the hackathon?
- **Cross-package imports are relative** (`../../shared/src/x.ts`), not `@stz/shared`, so tests run without `npm install` creating workspace symlinks. The workspace still exists so Track B can add deps to `functions/prime/package.json`.
- **TypeScript `^7.0.2`**: the version npm resolves today. tsconfig uses `erasableSyntaxOnly` (no enums or parameter properties), which keeps every file runnable under Node's type stripping.
