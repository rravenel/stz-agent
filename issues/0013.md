## Description

Prime's handler doesn't exist. It needs the spec's handler flow (worker first, stale-wake check, restore, drain and run), the append-only S3 log, the agent loop over the model and the REPL tool, and the proxy that sends model calls and REPL fetches through Com without waiting.

## Long Description

Spec §4.1, §5.1, §5.3:
- Handler flow §5.1 steps 1–5 against the comms interface from #0002 (use the in-memory fake in tests; the real worker from #0005 plugs in at #0008).
- Log writer: one S3 object per event, `If-None-Match: *`; on conflict take the next seq and log `lifecycle: seq_conflict`. Lifecycle events `start`, `restore`, `stale_wake`, `wake_sent`, `exit_idle`.
- Agent loop: runnable work is a `user.message`, a `model.response` with tool calls, or a settled eval. Model call = build request (adapter #0014), write body to S3, log `model.request`, send `http.request`, **don't wait**.
- Proxy: assign `request_id`, record in `state.pending_requests`, write body to S3, log `http.request`, send; on `http.response` read the body from S3 and resolve the REPL promise or feed the model response back.
- `/clear`: log `conv.clear`, reset model context, keep REPL and workspace.
- Dedupe inbound by `msg_id` (`seen_msg_ids`).
- Unit tests with fakes for S3, comms and the model: one full turn with a tool call whose fetch is answered in a later "run".

## Plan

**Scope.** #0013 is the loop, the log and the proxy. It also includes *minimal* checkpoint and exit steps, so a turn can span runs in a test. #0015 hardens the checkpoint: workspace sync, stale `pending_requests`, deleting messages after the checkpoint, and atomicity tests. #0016 adds the exit checklist, the stale-wake check and continuation. Keep those seams as small interfaces, so the later issues replace bodies, not call sites.

**Files**, all in `functions/prime/src/`. No changes to `functions/shared/`: the plan fits the A0 `PrimeState` and `LogEvent` as they are.

1. **`store.ts`: `ObjectStore`.**
   - Methods: `get(key) → Uint8Array | null`, `put(key, body)`, `putIfAbsent(key, body) → boolean` (S3 `If-None-Match: *`), and `list(prefix)`.
   - Ships with `MemoryStore`, the fake.
   - The real S3 version waits for the AWS SDK prerequisite above.
2. **`log.ts`: `LogWriter(store, run, conv, nextSeq)`.**
   - `append(kind, {corr_id, msg_id, body, body_ref})` writes `log/<seq>` with `putIfAbsent`.
   - On a conflict it takes the next seq, retrying until a write lands, then logs `lifecycle {event: "seq_conflict", wanted, got}`.
   - It keeps `state.next_seq` in step.
   - Bodies stay inline; anything large goes through `body_ref` (`bodies/…`).
   - Lifecycle events emitted here: `start` and `restore`, plus `exit_idle` from the minimal exit. `stale_wake` and `wake_sent` come with #0016.
3. **`proxy.ts`: `Proxy(store, comms, log, state)`.**
   - **`request_id`s:** `model-<seq>`, taken from the seq of its `model.request` event, and `repl-<rN>`, where `rN` is the REPL's own counter, which lives in the snapshot. Both stay unique across runs with no new state field.
   - **`send(purpose, {method, url, headers, body, auth}, tool_call_id?)`:** `put bodies/<id>.req`, record `state.pending_requests[id] = {purpose, tool_call_id, sent_at, timeout_s: 600}`, log `http.request`, then `comms.send("com", "http.request", {request_id, method, url, headers, body_ref, auth, timeout_s, purpose})`. REPL fetches always use `auth: "none"`.
   - **The REPL's `onFetch` is synchronous and must not re-enter the REPL**, so it only pushes onto an outbox. The loop flushes the outbox (the async S3 writes and sends) right after each `eval`/`resolvePending`.
   - **`onResponse(http.response)`:**
     - Unknown `request_id`: log `http.response` with `body: {dropped: "unknown request_id"}` and do nothing else.
     - Otherwise delete it from `pending_requests`, read `bodies/<id>.res` if `body_ref` is set, and log `http.response`.
     - **repl:** call `repl.resolvePending(rN, {status, headers, body})`, or `rejectPending(rN, error)` when `ok: false`.
     - **model:** hand the body to the loop.
4. **`loop.ts`: `Harness`, the agent loop over `state.model_context` (`Message[]`).**
   - **Inbound `user.message`:**
     - `markSeen` dedupe, so duplicates are skipped.
     - Log `user.message`.
     - `/clear`, exactly: log `conv.clear`, `conv++`, empty `model_context`, drop the model-purpose `pending_requests` (their late responses then log as unknown and are dropped), clear `open_tool_calls`. The REPL and the workspace stay.
     - Anything else: append `{role: "user", content: [{type: "text", text}]}`.
   - **Runnable:** the last context message is `user`, no model request is pending, and no tool call from the last assistant message is still open. Then make one model call:
     - **`normalize(messages)`** merges consecutive same-role messages, puts `tool_result` blocks first in a user message, and drops empty text blocks and empty messages (#0014 note 2).
     - Then `adapter.toRequest`, log `model.request` (with `body_ref` for the request body), and `proxy.send("model", …)`.
     - **Don't wait.** A user message that arrives mid-turn becomes a trailing user message, and `normalize` folds it in after the tool results.
   - **Model response:**
     - `adapter.fromResponse`. A `ModelResponseError` or `ok: false` logs `error` and ends the turn; the context is left valid.
     - Log `model.response` and append the assistant message.
     - For each `tool_call`, log `tool.call`.
     - **#0014 note 1:** if `input._invalid_json` is set, or `code` isn't a string, the tool result is an error: "arguments were not valid JSON: …". **Never eval it.**
     - Otherwise `repl.eval(id, code)`. `done` gives a tool result; `pending` adds the id to `open_tool_calls`.
   - **Tool result:**
     - Content is `JSON.stringify({value, stdout, stderr, error})`, truncated to 16 KB with a marker. `is_error` is set when `error` is present.
     - Log `tool.result` and append it as a `tool_result` block in a user message.
   - **After each `resolvePending`/`rejectPending`:** `take()` every id in `open_tool_calls`. Settled ones become tool results. When none is left open, the turn is runnable again.
   - **Turn ends** on `stop: "end_turn"` (or `max_tokens` or `other`) with no tool calls.
   - **`REPL_TOOL` description** (`models/turn.ts`): it says "the value of the last expression is returned" and "variables persist", and neither is true with the spec's async wrapper. Change it to "use `return` to return a value; declarations are local to one call, so keep anything you want later on `globalThis`". The tests should pin this wording.
   - **#0014 note 3:** add `OPENAI_MAX_TOKENS_FIELD=max_completion_tokens|max_tokens` (default `max_tokens`) to `adapterFromEnv`/`openaiAdapter`, with one test.
5. **`checkpoint.ts`: minimal, replaced by #0015.**
   - `load(store)`: read `prime/latest.json` → `state.json` + `repl.bin`, then `Repl.restore`; with no checkpoint, use `initialState()` + `Repl.create()`.
   - `save(store, state, repl)`: write `ckpt-<n+1>/state.json`, `repl.bin`, then `latest.json`, and log `lifecycle checkpoint`.
6. **`handler.ts`; `index.ts` exports `handler`.**
   - `createHandler(deps)`, where `deps` is `{comms(), store, adapter, replOptions, now}`, so tests inject fakes.
   - Flow:
     1. Start comms first and buffer deliveries.
     2. (The stale-wake check is a no-op until #0016.)
     3. Load the checkpoint and log `start`/`restore`.
     4. Drain the buffer and run the loop until nothing is runnable.
     5. Minimal exit: save the checkpoint, delete the held receipts, then `finalPoll(2000)`. If a message arrived, go back to step 4.
     6. Log `exit_idle`, `comms.stop()`, return.
   - Real wiring (`InMemoryComms` → the SQS worker, `MemoryStore` → `S3Store`) happens in #0008.

**Tests** (`loop.test.ts`, `log.test.ts`, `proxy.test.ts`) with `MemoryStore`, `InMemoryBus` (Prime, plus the test playing Com) and the mock Anthropic-format adapter:

- **Multi-run turn** (the acceptance test). Each run is a fresh handler invocation that restores from the store:
  - Run 1 sends a `user.message`; Prime sends a model `http.request` and exits.
  - The test, playing Com, writes a `tool_use` response calling `await fetch("https://example.com/x")`.
  - Run 2: the eval goes pending, Prime sends a REPL `http.request` and exits with a snapshot.
  - Run 3: the fetch response settles the eval, the tool result goes to the model, and Prime sends a model `http.request`.
  - Run 4: `end_turn` text, and Prime is idle.
  - Assert:
    - the log `kind` sequence, with contiguous seqs;
    - `pending_requests` is empty at the end;
    - the context alternates user and assistant;
    - the request bodies in `bodies/`.
- Redelivering the same `user.message` (same `msg_id`) changes nothing.
- An `_invalid_json` tool call gives an error tool result and the REPL is never called (spy).
- `/clear` resets the context, the REPL global survives, and a late model response for the old conversation is dropped.
- Log seq conflict: pre-create `log/<n>`, and the writer takes `n+1` and logs `seq_conflict`.
- `normalize`: merges, puts tool results first, drops empty text.
- `ok: false` model response: logs `error`, and the turn ends.
- Openai max-tokens field switch.
