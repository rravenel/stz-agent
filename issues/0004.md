## Description

The protocol rests on three Lambda behaviours nobody has observed yet: a sync invoke to a busy reserved-concurrency-1 function returns 429, the target keeps running after the caller aborts at 2 s, and an async self-wake lands within seconds of the instance exiting. Measure all three on a deployed stack.

## Plan

Design change from the Long Description: instead of a local script under `spikes/s2-wake/`, the spike is a **driver Lambda** that runs all three checks against a **target Lambda**, using the real SDK v3 client config (`maxAttempts: 1`, a 2 s `abortSignal`) and the production `classifyInvoke`. The person runs one command and pastes the JSON it returns. Both are the same bundle, `functions/s2spike/`, which is Track A-owned. Don't touch `functions/prime/` or `spikes/` (Track B).

Files: `functions/s2spike/src/{index.ts,analyze.ts,analyze.test.ts}`, `functions/build.mjs` (add `"s2spike"` to the list), `stz_agent/stz_agent_stack.py`, `tests/unit/test_stz_agent_stack.py`. **Do not** add `s2spike` to `functions/package.json` `workspaces`: that changes the lockfile, and only a person re-locks. It needs no `package.json`. `tsconfig` `include` and the test glob already cover `*/src/**`.

1. **`analyze.ts` (pure, tested now).** Types for the markers the target writes, `{ id, mode, cold, initAt, startAt, endAt }` (ms epoch), and a `Report` that the driver returns. `summarize(raw) → Report` with:
   - `check1`: `{ secondCall: WakeResult, errorName, reason, httpStatus, pass: secondCall.kind === "running" }`
   - `check2`: `{ firstCall: WakeResult, markerFound, markerEndMinusCallStartMs, pass: firstCall.kind === "started" && markerFound && ≈ 10 s (8–15 s) }`
   - `check3`: `{ gapMs: continued.startAt − parent.endAt, pass: gapMs < 10000 }`
   - `init`: `{ coldInvokeMs, warmInvokeMs, coldFlagSeen }`
   - plus `verdict: "all pass" | "<failing checks>"`.
2. **`index.ts` handler**, one bundle with the mode taken from the payload:
   - **Target modes:**
     - `ping`: returns `{cold}`. A module-level `let cold = true` is flipped after the first call; record `initAt` at module load.
     - `sleep {id, ms}`: waits `ms`, then writes marker `spikes/s2/<id>.json`.
     - `selfwake {id}`: writes the parent marker, sends `InvokeCommand({ FunctionName: own name, InvocationType: "Event", Payload: {mode: "continued", id} })` as the last action, and returns.
     - `continued {id}`: writes marker `<id>-continued.json`.
   - **Driver mode `drive`:**
     - (a) `ping` the target twice, timing both: the first is cold after deploy.
     - (b) Invoke `sleep {ms:10000}` with abort at 2 s and classify it (expect `started`); **immediately** invoke `ping` with no abort and classify it (expect `running`). Capture the raw error's `name`, `Reason` and `$metadata.httpStatusCode`.
     - (c) Poll S3 for the sleep marker, every 1 s for up to 20 s.
     - (d) Invoke `selfwake` and poll for `-continued` for up to 60 s.
     - (e) Return `summarize(...)` as JSON.
   - Every id is unique per run (`Date.now()` + random), so re-runs don't collide.
   - Env vars: `SPIKE_BUCKET`, `TARGET_FUNCTION_NAME`, `SELF_FUNCTION_NAME`.
3. **Stack**: add the two spike functions only when `env_name != "demo"` and context `spike_s2` isn't `"off"`. Pass a `spike_s2: bool` constructor flag from `app.py`, default True; tests pass it explicitly.

   - **driver** `<stack>-s2-driver`: 128 MB, timeout 3 min, no reserved concurrency.

## Run-book

Run after `scripts/deploy.sh` (dev env, not `demo`; the spike is skipped there and with `-c spike_s2=off`). `<env>` is your stack's env name (default: your OS username).

```sh
aws lambda invoke --profile stz-dev --function-name StzAgent-<env>-s2-driver \
  --cli-read-timeout 200 --payload '{"mode":"drive"}' --cli-binary-format raw-in-base64-out /tmp/s2.json && cat /tmp/s2.json
```

The `aws` line prints `{"StatusCode": 200, "ExecutedVersion": "$LATEST"}`; the driver takes about 30–90 s. Then `cat` prints the report. A passing one looks like:

```json
{"check1":{"secondCall":{"kind":"running","detail":"ReservedFunctionConcurrentInvocationLimitExceeded"},
           "errorName":"TooManyRequestsException","reason":"ReservedFunctionConcurrentInvocationLimitExceeded","httpStatus":429,"pass":true},
 "check2":{"firstCall":{"kind":"started","detail":"aborted"},"markerFound":true,"markerEndMinusCallStartMs":10050,"pass":true},
 "check3":{"gapMs":1200,"pass":true},
 "init":{"coldInvokeMs":600,"warmInvokeMs":40,"coldFlagSeen":true},
 "verdict":"all pass"}
```

- **check1**: second sync call to the busy reserved-concurrency-1 target gets 429.
- **check2**: target kept running after the 2 s abort; marker lands 8–15 s after the call.
- **check3**: async self-wake starts < 10 s after the parent's marker.
- **init**: cold vs warm ping round trip (feeds `WAKE_ACK_TIMEOUT`). Only the **first run after a deploy** is cold (`coldFlagSeen: true`).

Run it **twice** in a row and paste both outputs. If the `aws` line shows `"FunctionError"`, paste `/tmp/s2.json` anyway (it holds the error).
