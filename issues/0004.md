## Description

The protocol rests on three Lambda behaviours nobody has observed yet: a sync invoke to a busy reserved-concurrency-1 function returns 429, the target keeps running after the caller aborts at 2 s, and an async self-wake lands within seconds of the instance exiting. Measure all three on a deployed stack.

## Long Description

Spec §10 S2, protocol §4, open-questions "Risks":
- A spike function (or Prime stub) that sleeps 10 s and then writes an S3 marker; a local script under `spikes/s2-wake/` that invokes it with `InvocationType: RequestResponse`, `maxAttempts: 1` and a 2 s `abortSignal`.
- Check 1: invoke twice in a row; record the second call's error name and reason (`ReservedFunctionConcurrentInvocationLimitExceeded`?).
- Check 2: abort at 2 s; confirm the S3 marker appears ~10 s later.
- Check 3: from inside the function, send `InvocationType: Event` `{reason:"continue"}` as the last action; measure the gap until the next invocation starts (CloudWatch or S3 timestamps).
- Also note cold vs warm init time for the stub (feeds `WAKE_ACK_TIMEOUT`).
- Record results in `docs/protocol.md` (remove the **[VERIFY]** marker) and move the answers out of `docs/open-questions.md`.
- Write a `## Run-book` section in this issue: the exact commands a person runs after `scripts/deploy.sh`, and what each prints. The run itself is owner issue #0022.
