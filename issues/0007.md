## Description

Doorman is a stub. It must enqueue user messages to Prime and wait up to ~20 s for Prime's ack, pre-wake Prime on `POST /wake`, and serve the log from S3 on `GET /events` without ever waking Prime.

## Long Description

Spec §7; protocol §7.1:
- `POST /messages {msg_id, text}` (client-generated `msg_id`; `/clear` passes through as text): enqueue `user.message`, run the delivery monitor against `doorman-messages` for up to ~20 s; `202 {msg_id}` on ack, `503` otherwise.
- `POST /wake`: sync-wake Prime with `{reason:"prewake"}`, return `202` immediately; no message, no ack loop.
- `GET /events?after=<seq>`: list and read `log/` objects after `seq` from S3. Never touches queues or invokes anything.
- Delete every message read from `doorman-messages`, including stale acks.
- Static bearer token from an env var on every route; `401` otherwise.
- Doorman is request-scoped: it can reuse the delivery-monitor logic from #0005 in-process rather than a worker thread.
- Unit tests: 202 on ack, 503 on timeout, stale acks deleted, events pagination, auth.

## Plan

Files (all in `functions/doorman/src/`): `index.ts` (replaces the stub), `doorman.ts`, `http.ts`, `events.ts`, `aws.ts`, `doorman.test.ts`, `events.test.ts`, `http.test.ts`; update `index.test.ts`.

1. **`http.ts`** (pure): parse an API Gateway HTTP API **payload v2** event: `requestContext.http.method`, `rawPath`, `headers` (lower-case), `queryStringParameters`, `body` with `isBase64Encoded`. Return `{statusCode, headers: {"content-type": "application/json"}, body: JSON.stringify(...)}`.
   - **Auth**: `authorization: Bearer <token>` compared with `crypto.timingSafeEqual` against `API_TOKEN` (compare lengths first). Missing or wrong → `401 {error: "unauthorized"}` on every route.
   - Unknown route → 404. Malformed JSON → 400. Never log the token or the Authorization header.
2. **`POST /messages`** (`doorman.ts`, `postMessage(deps, body)`):
   - Validate `{msg_id, text}`: `msg_id` is 1–128 chars of `[A-Za-z0-9._-]`; `text` is a string ≤ 64 KB (SQS limit with headroom). Otherwise 400. `/clear` passes through as text.
   - Create a **fresh** `CommsCore("doorman", queue, wake, log, { pollWaitSeconds: 1 })` per request and `start()` it.
   - `send("prime", "user.message", {text}, {msg_id})`.
   - Wait until `unackedCount() === 0` (check every 100 ms), up to `ACK_WAIT_MS = 20000`. The monitor wakes Prime at 3 s and again at 18 s by itself.
   - Then `await comms.stop()`. That's at most one 1 s long poll, and it must finish before returning, because a frozen Lambda would otherwise resume a stale poll.
   - Ack → `202 {msg_id}`. No ack → `503 {msg_id, error: "prime did not ack; retry with the same msg_id"}`.
   - Log each wake result as a JSON line.
3. **`POST /wake`** (`prewake(deps)`): Invoke Prime with `RequestResponse` and payload `{reason: "prewake"}`, using `new LambdaClient({maxAttempts: 1})` and `abortSignal: AbortSignal.timeout(2000)`. Classify the result with the shared `classifyInvoke`, log it, and **always** return `202 {wake: result.kind}`. No message, no ack loop.
4. **`GET /events?after=<seq>`** (`events.ts`, `listEvents(store, after, limit)`):
   - `after` defaults to −1, and must be an integer ≥ −1 (else 400). `limit` defaults to 100, max 500.
   - List with `ListObjectsV2(Prefix: "log/", StartAfter: after >= 0 ? logKey(after) : undefined, MaxKeys: limit)`. Keys sort numerically because `logKey` zero-pads. Keep only keys where `seqFromLogKey` isn't null, fetch them in parallel (concurrency ≤ 10), and parse the JSON.
   - Return `200 {events, next_after: <last seq or after>, more: IsTruncated}`. A corrupt object is skipped with a logged warning, not a 500.
   - **Never touches queues or invokes anything.** Assert this in a test by giving it deps without comms or wake.
5. **`aws.ts`**: thin SDK adapters (`S3LogStore.list/getText`, `PrimeInvoker.invoke(payload)`) plus `fromEnv` wiring. `index.ts` builds the deps once per container (module scope) and routes events through `http.ts`.
6. **Tests** (`node:test`; fake ports in the style of `comms-core.test.ts`: an in-memory `QueuePort` keyed by endpoint plus a scripted `WakePort`; `mock.timers` where waits matter):
   - **202 on ack**: a fake Prime consumer acks after 500 ms → 202 with the same `msg_id`, and the queue held a `user.message` whose `msg_id` is the client's.
   - **503 on timeout**: no consumer → 503 after 20 s. Exactly two wakes were attempted (3 s and 18 s), and the message was sent once.
   - **Retry**: a second POST with the same `msg_id` enqueues again with the same `msg_id`. Prime dedupes it; Doorman doesn't.
   - **Stale acks deleted**: an ack for an unknown `msg_id` sitting in `doorman-messages` is deleted and doesn't count as our ack.
   - **Auth**: missing, wrong or right token on all three routes, and the token never appears in captured logs.
   - **Validation**: bad `msg_id`, oversized text, bad JSON, unknown route.
   - **Prewake**: 202 for each of `running`/`started`/`failed`/`error`, and the payload is `{reason: "prewake"}`.
   - **Events**: empty bucket; `after` filtering; `limit` and `more`; non-log keys ignored; corrupt object skipped; bad `after` → 400.
   - **`http.ts`**: base64 body and header case.
7. **Verify**: with the usual exports, `scripts/check.sh` → `CHECK OK`, with the new tests counted and `build-functions` still bundling `doorman`.
8. **Git** (per `Issues.md`): code commits go on the branch; issue-file edits go on `main` only. Stage by path.

- Matches the plan; the token and Authorization header are never logged; ack wait (20 s) + final poll (1 s) fits the 29 s Lambda timeout.
- Non-blocking: two concurrent `POST /messages` on different containers poll the same `doorman-messages` queue, so one can receive and delete the other's ack as unknown. That request returns 503 and the client's retry (same `msg_id`, Prime dedupes and re-acks) recovers it. Fine for the single-session demo.
