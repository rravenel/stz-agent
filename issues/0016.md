## Description

Prime must return only when the six-step exit checklist passes, take the stale-wake path for prewakes, and at 12 minutes checkpoint and send an async self-wake as its very last action.

## Root cause

Prime's exit was a minimal placeholder (checkpoint, delete, final poll). It had no stale-wake check, didn't wait for acks, had no 12-minute continuation and no self-wake. Three #0015 review notes were open.

## Fix

Branch `track-b/0016-exit-continuation`, commit `0051592`. It follows the `## Plan`.

- **`handler.ts`**
  - **Stale wake:** no message within `staleWakeMs` and `reason !== "continue"` → `stale_wake`, return. It reads only `latest.json` and `state.json` (`peekState`), for the log seq. No restore, no checkpoint.
  - **Exit checklist,** in spec order:
    1. drain the inbox and step the harness;
    2. assert `!repl.busy`;
    3. poll `unackedCount()`; an inbound message goes back to step 1, and past `hardStopMs` Prime logs an `error` and proceeds;
    4. `saveCheckpoint`;
    5. delete the held messages;
    6. `finalPoll(idleGraceMs)`, and a message goes back to step 1.
  - **Continuation at `runDeadlineMs`:**
    - no `step()` after the deadline, so no new model calls;
    - inbound messages are absorbed into state until `hardStopMs − 60 s`, and left in SQS after that;
    - then steps 2–5, then `exit_deadline`, then `selfWake({reason: "continue"})` last.
  - **`RunSummary.exit`** is `idle`, `deadline` or `stale_wake`.
- **`log.ts`:** a conflict with a seq held by a `stale_wake` event isn't reported as `seq_conflict`. It's expected, because a stale wake logs without checkpointing.
- **`checkpoint.ts`:** `peekState`, and `workspaceSkipped` returned from `loadCheckpoint`.
- **#0015 review note 1:** the comment now says plainly that the workspace isn't versioned per checkpoint. Decision: keep spec §5.4's single shared `workspace/` prefix for v0.
- **#0015 review note 2:** buffered responses are drained before `failStale`.
- **#0015 review note 3:** `syncDown` skips and reports bad keys (malformed, or a file clashing with a directory). The `restore` event logs them as `workspace_skipped`.
- **Beyond the plan: an ordering bug from #0013.** A user message that arrived while a model call was in flight was stored *before* the reply, so the model never answered it.
  - **Fix:** such messages are marked `queued` (a harness-only field on `Message`, which adapters ignore). The reply is inserted before them, and the flags are cleared.
  - **Found by:** the continuation test.
- **`repl.ts`:** `Repl.busy`.
- **`test-world.ts`:** a passive Com that acks during runs (`comAcks`, default on), plus `deps` overrides.

## Gotchas

- **For #0008:**
  - `selfWake` must be wired to `lambda:InvokeFunction` with `InvocationType: "Event"`.
  - The function needs the event-invoke config `MaximumEventAgeInSeconds = 60` and `MaximumRetryAttempts = 0` (protocol §4.2).
  - Without `selfWake`, a run that hits the deadline throws after its checkpoint, so nothing is lost but the turn stalls.
- **The stale-wake wait uses wall-clock time** (`Date.now()`), not the injected `now`. Tests set `staleWakeMs: 50`.
- **Hard stop with outbound unacked:** Prime proceeds rather than be killed mid-checkpoint. Its comms worker dies with it, so the request's delivery then depends on Com's own next wake. That's logged as an `error`.

## Long Description

Spec §5.1 step 3, §5.5; protocol §4.2, §7.3, §8:
- Exit checklist in order: harness idle, REPL quiescent, outbound acked (unacked set empty), checkpoint durable, held messages deleted, final poll of `IDLE_GRACE` (2 s) empty; a message in the final poll goes back to step 1. Pending Com requests never block exit.
- Stale-wake check: no non-ack message within ~1 s and `reason != "continue"` → log `stale_wake`, stop the worker, return without restoring (this is the `prewake` path).
- Continuation at 12 min: stop starting new work, finish the current eval, run checklist steps 2–5, send `InvocationType: Event` `{reason:"continue"}` last, log `exit_deadline`, return.
- Log `exit_idle` / `exit_deadline` / `checkpoint`.
- Unit tests with fake clock and fakes: each checklist step blocks exit when unmet; prewake path; continuation sends the self-wake last.

## Plan

All changes are in `functions/prime/src/handler.ts`, unless a step says otherwise. New `PrimeDeps` fields, all with spec defaults:

| Field | Default | What it is |
|---|---|---|
| `staleWakeMs` | 1000 | how long to wait for a first message (spec §5.1 step 3) |
| `idleGraceMs` | 2000 | the final poll |
| `runDeadlineMs` | 12 min | when the continuation starts |
| `hardStopMs` | 14 min | the safety stop |
| `ackPollMs` | 50 | how often to check the unacked set |
| `selfWake({reason: "continue"})` | (none) | the async self-invoke, injected |

`RunSummary.exit` becomes `"idle" | "deadline" | "stale_wake"`.

1. **Stale-wake check.** Wait up to `staleWakeMs` for a non-ack message. If none arrives and `reason !== "continue"`:
   - log `lifecycle stale_wake`, stop the worker, and return without restoring;
   - read only `latest.json` and `state.json`, to get `next_seq` for the log event;
   - no REPL, no workspace sync and no checkpoint.

   The next real run reuses that seq. **`LogWriter` treats a conflict with a `stale_wake` event as harmless** and doesn't log `seq_conflict` for it. Otherwise every prewake would look like a crash.
2. **Restore,** then **drain what's already buffered before `failStale`** (#0015 note 2). A response waiting for a request just past its deadline is then used, not dropped.
3. **Exit checklist, in spec order.** Any message that arrives goes back to step 1.
   1. **Harness idle:** the inbox is drained and `harness.step()` has sent any runnable model call.
   2. **REPL quiescent:** `repl.busy` is false. Evals are synchronous and drain their jobs, so this always holds here; it's asserted.
   3. **Outbound acked:** poll `comms.unackedCount()` every `ackPollMs`. A message that arrives meanwhile goes back to step 1. At `hardStopMs` Prime logs an `error` and continues anyway, rather than being killed mid-checkpoint.
   4. **Checkpoint durable.**
   5. **Held messages deleted.**
   6. **Final poll** of `idleGraceMs`. If it's empty, log `exit_idle` and return.

   Pending Com requests never block exit.
4. **Continuation at `runDeadlineMs`.**
   - **No new model calls:** `step()` isn't called again.
   - **Messages still arriving are absorbed into state** (a `user.message` is appended, and an `http.response` is matched and its tool calls run) while `elapsed < hardStopMs − 60 s`, so they're covered by the checkpoint and deleted. Leaving them unprocessed would hide them for the 15-minute visibility timeout.
   - Then steps 2–5, then log `lifecycle exit_deadline`, then **`selfWake({reason: "continue"})` as the very last action**, then return.
   - The `continue` run skips the stale-wake wait and picks up the runnable turn.
5. **#0015 note 3:** `syncDown` skips a malformed `workspace/` key instead of throwing. It returns the skipped keys, which go in the `restore` log event.
6. **#0015 note 1:** decision: keep one shared `workspace/` prefix, as spec §5.4 lays it out. Fix the `checkpoint.ts` comment: a crash after `syncUp` but before `latest.json` restores the previous state and REPL alongside the newer workspace. Versioning the workspace per checkpoint is left for after the hackathon.

**Tests** (`exit.test.ts`; the World gets a passive Com that acks during runs, which can be turned off):
- **Prewake with no message:** `stale_wake`, no checkpoint, no restore. A later real run logs no `seq_conflict`.
- **`continue` with no message:** restores and exits idle.
- **Unacked blocks exit:** with no Com acking, the handler doesn't return and writes no checkpoint. Once Com acks, it checkpoints and exits.
- **A message during the final poll** is processed in the same run (two checkpoints), then Prime exits.
- **Continuation:** the clock passes 12 min during the first message.
  - The second message is absorbed into state but gets no model call.
  - The order is: checkpoint, deletes, `exit_deadline`, then `selfWake`.
  - The `continue` run sends the model call.
- **A buffered response just past its deadline** is used, not failed as lost.
- **A malformed `workspace/` key** is skipped and logged, and the restore succeeds.
