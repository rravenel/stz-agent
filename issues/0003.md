## Description

`StzAgentStack` is still the scaffold. It needs the bucket, the three message queues with DLQs, three stub Lambdas, the HTTP API and the model-key secret, with the spec's concurrency, timeout and IAM rules, and CDK assertion tests for them.

## Long Description

Per spec §2, §8 and protocol §2, §4.2:
- S3 bucket (block public access, enforce SSL, `RemovalPolicy.DESTROY` + auto-delete for dev stacks).
- SQS standard queues `doorman-messages` (visibility 30 s, retention 60 s), `prime-messages` (visibility 15 min), `com-messages` (30 s); DLQs for prime and com with `maxReceiveCount` 5. **No event source mappings.**
- Lambdas Doorman (128 MB), Prime (2 GB, timeout 15 min), Com (128 MB, timeout 15 min), Node.js runtime, **reserved concurrency 1** each, code from the esbuild bundles of #0001 (`lambda.Code.from_asset("functions/dist/<name>")`). Stub handlers until A2/B2.
- Prime event-invoke config: `MaximumEventAgeInSeconds=60`, `MaximumRetryAttempts=0`.
- IAM: Doorman can invoke Prime; Prime can invoke Com and itself; Com can invoke Prime. Each function reads its own queue and sends to the queues it writes. Only Com can read the Secrets Manager secret.
- HTTP API → Doorman (`POST /messages`, `POST /wake`, `GET /events`); bearer token env var.
- Pass queue URLs, bucket name and function names as env vars; output the API URL.
- pytest assertions for every bullet above in `tests/unit/` (replace the placeholder test).

## Plan

Files: `stz_agent/stz_agent_stack.py`, `app.py` (token plumbing only), `tests/unit/test_stz_agent_stack.py`. Nothing under `functions/`.

1. **Stack signature.** `StzAgentStack(scope, id, *, api_token: str, **kwargs)`. `app.py` passes `api_token` from context `-c api_token=…`, else env `STZ_API_TOKEN`, else `"build-placeholder"` **only when** `env_name == "build"` (what `scripts/build.sh` synthesizes); any other env without a token raises `ValueError("set STZ_API_TOKEN or -c api_token=…")`. Tests pass `api_token="test-token"`.
2. **Explicit function names, no cross-references between functions.** Prime↔Com invoke each other and Prime invokes itself; referencing `fn.function_arn` / `fn.function_name` across them creates a CloudFormation dependency cycle. So:
   - `names = {f: f"{self.stack_name}-{f}" for f in ("doorman", "prime", "com")}` (e.g. `StzAgent-rene-prime`; max 31+9+8 < 64 chars), set as each function's `function_name`.
   - Build ARNs as strings: `self.format_arn(service="lambda", resource="function", resource_name=name, arn_format=ArnFormat.COLON_RESOURCE_NAME)`.
   - Grant invoke with `iam.PolicyStatement(actions=["lambda:InvokeFunction"], resources=[arn])` added to the caller's role, not `fn.grant_invoke`.
   - Env vars use the plain name strings. #0010 relies on this naming (`/aws/lambda/StzAgent-<env>-<fn>`); keep it.
3. **Bucket**: `s3.Bucket(block_public_access=BLOCK_ALL, enforce_ssl=True, encryption=S3_MANAGED, removal_policy=DESTROY, auto_delete_objects=True)`. Note: auto-delete adds a provider `AWS::Lambda::Function`, so tests must match functions by name, not count them.
4. **Queues** (standard; let CDK name them): `doorman-messages` vis 30 s, retention 60 s, no DLQ; `prime-messages` vis 15 min + DLQ (`max_receive_count=5`); `com-messages` vis 30 s + DLQ (5). DLQ retention 14 days.
5. **Functions** via one helper: `lambda_.Function(runtime=NODEJS_22_X, architecture=X86_64, handler="index.handler", code=Code.from_asset(str(ROOT / "functions" / "dist" / name)), reserved_concurrent_executions=1)`, with a `logs.LogGroup` per function named `/aws/lambda/<name>` with 1-week retention and `DESTROY`, passed as `log_group=`.
   - `ROOT = Path(__file__).resolve().parents[1]`. If `functions/dist/<name>/index.mjs` is missing, raise `FileNotFoundError("run scripts/build.sh first")`.
   - Doorman: 128 MB, timeout **29 s** (HTTP API's integration cap is 30 s; it waits ~20 s for an ack).
   - Prime: 2048 MB, timeout 15 min. `fn.configure_async_invoke(max_event_age=Duration.seconds(60), retry_attempts=0)`.
   - Com: 128 MB, timeout 15 min.
6. **Env vars** (all three get the common set): `BUCKET_NAME`, `DOORMAN_QUEUE_URL`, `PRIME_QUEUE_URL`, `COM_QUEUE_URL`, `DOORMAN_FUNCTION_NAME`, `PRIME_FUNCTION_NAME`, `COM_FUNCTION_NAME`. Plus Doorman `API_TOKEN`, Com `MODEL_SECRET_ARN`. Write these names into `## Fix`; A2 and Track B code against them.
7. **IAM** (least privilege, per protocol §2/§4):
   - Invoke: Doorman→Prime; Prime→Com, Prime→Prime; Com→Prime.
   - Queues: each fn `grant_consume_messages` on its own queue. Sends: Doorman→prime-messages; Prime→doorman-messages, com-messages; Com→prime-messages (the arrows in the spec §2 diagram).
   - S3: Prime `grant_read_write`; Com `grant_read_write` (reads `.req`, writes `.res`); Doorman `grant_read` (log).
   - Secret: `secretsmanager.Secret(self, "ModelKeys", description="Model API keys JSON; set by a person")`, `grant_read` to **Com only**.
8. **HTTP API**: `apigwv2.HttpApi` with `HttpLambdaIntegration` to Doorman for `POST /messages`, `POST /wake`, `GET /events`. No authorizer (Doorman checks the bearer token).
9. **Outputs**: `ApiUrl`, `BucketName`, and the three function names.
10. **No event source mappings** anywhere.
11. **Tests** (`tests/unit/test_stz_agent_stack.py`, replace placeholder; module-scoped fixture builds the template once): bucket public-access block + SSL deny policy; 3 queues' visibility/retention + 2 DLQs with `maxReceiveCount` 5; `resource_count_is("AWS::Lambda::EventSourceMapping", 0)`; each named function's memory/timeout/runtime/`ReservedConcurrentExecutions: 1`; `AWS::Lambda::EventInvokeConfig` for Prime with 60/0; invoke statements per caller (and **no** Doorman→Com); `secretsmanager:GetSecretValue` appears in exactly one policy and it's attached to Com's role; HTTP API has the 3 routes; env var keys present; outputs exist. Also a test that synthesizing without a token for a non-`build` env raises (test the `app.py` helper by factoring it into a small function, e.g. `stz_agent/config.py: resolve_api_token(env_name, ctx)`).
12. **Verify**: with the three exports above, `scripts/check.sh` → `CHECK OK`. Paste the summary lines into `## Verification`.
13. Commit on `track-a/0003-cdk-stack`: code commit, then `#0003 Notes: implementation drafted`. Leave status `in-progress`; reviewer resolves.
